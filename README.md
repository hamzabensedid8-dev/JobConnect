# JobConnect — international work-contract platform

Candidates submit contract requests for free, get a reference code and track the
outcome. Recruiters publish contracts, candidates pay a JobConnect fee plus the
recruiter's price by card, and every decision carries a reason.

**Web:** <https://jc.jobconnectdz.workers.dev>
**Android (admin console included):** see the latest release on GitHub
**Interface:** English only, responsive (mobile-first), light and dark themes

---

## What the platform does

| Feature | Implementation |
|---|---|
| Candidate accounts | Free, forever. CV upload required at sign-up (PDF/DOC/DOCX, 5 MB). |
| Reference code | `JC-YYYY-XXXXXXXXXX`, unique, trackable without an account. |
| Request status | `pending` → `accepted` / `rejected`. A rejection **requires a reason of at least 5 characters**, enforced by a database `CHECK` constraint and by the API. |
| Target response time | 5 to 20 minutes, configurable. `response_due_at` is computed at creation, the SLA state (remaining / overdue / answered in N min) is exposed on every read. |
| Candidate payment | JobConnect fee **+** recruiter price per contract. Card only, processed by **Stripe Checkout** (Visa / Mastercard). |
| Receipt and documents | PDF receipt generated by the Worker, e-mailed through Resend after Stripe confirms, available in the dashboard too. |
| Recruiter gating | A recruiter **cannot publish** without an active subscription: **Recruiter Pro $95/month** or the promotional plan. Enforced server-side (`402`). |
| Contract publishing | Admin publishes directly; recruiters go through moderation. Price per contract is configurable per job. |
| Admin app | Android WebView app with the whole admin console bundled inside the APK. No admin page exists on the website. |
| Messaging | Telegram-style: candidate ↔ admin, candidate ↔ recruiter (only the recruiter who published the job), recruiter ↔ admin. Deleting a message or a thread for **both** sides is admin-only. |
| Dashboard | Revenue, SLA compliance, subscriptions, payments, requests, jobs, chats, e-mail log, platform settings. |

## Architecture

| Layer | Technology |
|---|---|
| API + web app | Cloudflare Workers (one ES module, 7 assets inlined at build time) |
| Database | Supabase Postgres 17 (`eu-west-2`) through PostgREST |
| Resume storage | Supabase Storage, private bucket `cvs` |
| Passwords | Postgres `pgcrypto` bcrypt cost 11 via RPC (keeps the Worker inside its CPU budget) |
| Sessions | HS256 JWT signed with WebCrypto, 12 h |
| Payments | Stripe Checkout + signed webhook (`stripe-signature`, HMAC-SHA256, 5-minute replay window, idempotent) |
| E-mail | Resend REST API, every attempt journalised in `email_log` |
| Android | WebView shell + `WorkManager` notifications + bundled `assets/admin.html` |
| CI | GitHub Actions builds the APK on every change under `android/` |

**Nothing is faked.** Without `STRIPE_SECRET_KEY` the API returns
`503 Payments are not configured` instead of pretending to charge. Without
`RESEND_API_KEY` every e-mail is written to `email_log` with status `skipped`
instead of being reported as sent. The admin console shows both integrations as
`not configured` until real keys are supplied.

## Setup

### 1. Database

Run, in order, against the Supabase project (SQL editor or
`POST /v1/projects/{ref}/database/query`):

```
schema.sql
schema_messaging.sql
schema_billing.sql
```

Then create the first administrator (never commit this password):

```sql
insert into public.users (name, email, password_hash, role)
values ('Administrateur', 'admin@jobconnect.example',
        public.jc_hash_password('REPLACE_WITH_A_LONG_PASSWORD'), 'admin');
```

### 2. Worker

```bash
cp .env.example .env      # fill it in
set -a && . ./.env && set +a
npm run deploy            # build.js + scripts/deploy.js
```

### 3. Stripe (real payments)

1. Create a Stripe account and switch to live keys when ready.
2. Add a webhook endpoint pointing at
   `https://<your-worker>/api/webhooks/stripe`, subscribed to
   `checkout.session.completed`, `checkout.session.expired` and
   `payment_intent.payment_failed`.
3. Put the signing secret in `STRIPE_WEBHOOK_SECRET` and the secret key in
   `STRIPE_SECRET_KEY`, then redeploy.

Cards are typed on Stripe's hosted page: JobConnect never sees or stores card
data, which keeps the integration out of most PCI scope.

### 4. E-mail

Create a Resend API key and a verified sending domain, then set
`RESEND_API_KEY` and `MAIL_FROM` (`JobConnect <no-reply@yourdomain>`).

### 5. Android APK

The workflow `.github/workflows/android.yml` builds a debug APK on every push
that touches `android/`. Add the repository secret `ADMIN_CLIENT_KEY` (same value
as the Worker secret) and optionally the variable `SITE_URL`. The APK is attached
to the run and published as a release asset.

## Security

- Row Level Security on every table; the Worker is the only client and uses the
  `service_role` key, stored as an encrypted Worker secret.
- Passwords hashed with bcrypt in Postgres; the hash functions are not executable
  by `anon` or `authenticated`.
- Admin accounts cannot sign in from the browser: the API requires the
  `x-jc-client-key` header that only the APK carries. There is no admin route on
  the public site (verified by test).
- Resumes live in a **private** bucket; a recruiter can only download a CV
  attached to a job they own.
- Uploads limited to 5 MB and to `.pdf` / `.doc` / `.docx`; storage keys are
  UUIDs, never user-supplied filenames.
- Stripe webhooks: HMAC signature verification, 5-minute replay window,
  constant-time comparison, idempotent processing.
- Rate limits per IP on login, registration and public requests.
- Every admin action is written to `audit_log`.
- Multipart parsing is done byte-level in the Worker because the runtime's
  `request.formData()` flattened file parts into strings and silently dropped
  resumes.

## Tests

```bash
BASE=https://... ADMIN_PASSWORD=... ADMIN_CLIENT_KEY=... node scripts/e2e-v4.mjs
BASE=https://... STRIPE_WEBHOOK_SECRET=... node scripts/e2e-payments.mjs
BASE=https://... node scripts/e2e-chat.mjs
```

The suites cover registration, role isolation, subscription gating, pricing,
SLA arithmetic, mandatory rejection reasons, Stripe signature handling, receipt
generation, idempotency, messaging privacy and admin-only deletion.

## Limitations and next steps

- Stripe and Resend keys are **not** included: the code is real, the accounts are
  yours to create. Until they exist, payments return `503` and e-mails are logged
  as `skipped`.
- Subscription renewal is not automated: each period must be paid again. Adding
  Stripe Billing subscriptions (with `invoice.paid` webhooks) is the natural next
  step.
- No malware scanning on uploads; add it before accepting third-party resumes at
  volume.
- Notifications in the app use `WorkManager` polling (15-minute minimum on
  Android). FCM would give instant delivery.
- Legal review is required for privacy, recruitment, subscription and
  auto-renewal rules in every market served.
- JobConnect does not guarantee a visa, an offer or employment.
